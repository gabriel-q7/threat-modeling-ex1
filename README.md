# Payment Fintech Threat Modeling Exercise

## Overview
This is a self-guided threat modeling exercise for **PayFlow** - a fictional payment fintech platform. Work through each file sequentially to learn threat modeling concepts while building practical security knowledge.

## The Fictional System: PayFlow

PayFlow is a modern payment platform that allows:
- Users to create accounts and link bank accounts
- Send/receive money between users
- Request payments
- View transaction history
- Set up recurring payments
- Integration with merchant APIs

## Exercise Structure

Work through the files in this order:

1. **01-system-architecture.md** - Understand the system you're modeling
2. **02-assets-and-trust-boundaries.md** - Identify what you're protecting
3. **03-data-flows.md** - Map how data moves through the system
4. **04-threat-identification.md** - Identify potential threats using STRIDE
5. **05-threat-scenarios.md** - Develop specific attack scenarios
6. **06-risk-assessment.md** - Prioritize and assess risks
7. **07-mitigations.md** - Design security controls
8. **08-action-plan.md** - Create your remediation roadmap

## How to Use This Exercise

- Complete the TODOs in each file sequentially
- Don't skip ahead - each builds on previous work
- Think like an attacker, but also like a defender
- Reference real-world incidents when they come to mind
- Take breaks between files to let concepts sink in

## Learning Objectives

By completing this exercise, you'll learn to:
- Systematically analyze system security
- Think about security early in design
- Apply the STRIDE threat modeling framework
- Prioritize security work based on risk
- Document threats and mitigations effectively

## Time Estimate

- Quick pass: 2-3 hours
- Thorough analysis: 6-8 hours
- Deep dive with research: 12+ hours

Start with file `01-system-architecture.md` when ready!
